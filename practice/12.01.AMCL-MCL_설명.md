# MCL / AMCL 이해하기 — 로봇은 어떻게 자신의 위치를 알까?

---

## 핵심 한 줄 요약

> **"파티클(가상 로봇 1000개)을 뿌리고, 센서 데이터와 맞지 않는 것을 제거하면서 → 살아남은 파티클들의 평균이 로봇의 위치가 된다."**

---

## 0. 왜 이게 필요한가?

로봇이 바퀴를 굴려서 이동량을 계산하는 방식을 **오도메트리(Odometry)** 라고 합니다.  
하지만 바퀴가 미끄러지거나 노면이 고르지 않으면 **오차가 쌓여** 실제 위치와 점점 달라집니다.

```
실제 경로:   ──────────────────→
오도메트리:  ───────────────────⤴  (점점 틀어짐)
```

이 문제를 해결하기 위해 **LiDAR(레이저 거리 센서)** 데이터를 지도와 비교해 위치를 보정하는 알고리즘이 **MCL** 입니다.

---

## 1. 등장인물 소개

| 용어 | 쉬운 설명 |
|------|----------|
| **파티클 (Particle)** | "로봇이 여기 있을 수도 있다"는 가설 하나. 위치(x, y)와 방향(θ)으로 표현 |
| **가중치 (Weight)** | 그 가설이 얼마나 그럴듯한가? (센서 데이터와 얼마나 일치하는가) |
| **Occupancy Grid** | 공간을 격자로 나눠 각 칸이 장애물인지(100) 빈 공간인지(0) 저장한 지도 |
| **LiDAR 스캔** | 레이저를 360도로 쏴서 각 방향의 장애물까지 거리를 측정한 데이터 |
| **GT (Ground Truth)** | 실제 로봇 위치 (시뮬레이션에서만 알 수 있는 정답) |

---

## 2. 전체 흐름 (MCL 3단계)

```
┌─────────────────────────────────────────────────────┐
│                                                     │
│  초기화: 맵 전체에 파티클 N개 무작위 배포            │
│          (로봇 위치를 전혀 모르는 상태)              │
│                      ↓                              │
│  ┌─────────────────────────────────────────────┐    │
│  │  루프 반복 (로봇이 이동할 때마다)             │    │
│  │                                             │    │
│  │  Step 1. Motion Update (예측)               │    │
│  │    오도메트리만큼 파티클 전부 이동           │    │
│  │    + 약간의 노이즈 추가 (불확실성 표현)      │    │
│  │              ↓                              │    │
│  │  Step 2. Sensor Update (관측)               │    │
│  │    각 파티클에서 LiDAR를 쏴봄               │    │
│  │    실제 스캔과 비교 → 가중치 계산            │    │
│  │              ↓                              │    │
│  │  Step 3. Resampling (리샘플링)              │    │
│  │    가중치 높은 파티클은 복제                │    │
│  │    가중치 낮은 파티클은 제거                │    │
│  └─────────────────────────────────────────────┘    │
│          파티클이 실제 위치로 수렴!                  │
└─────────────────────────────────────────────────────┘
```

---

## 3. 단계별 상세 설명

### Step 1 — 지도(Occupancy Grid) 만들기

```python
grid[cy, cx] = 100  # 장애물
grid[cy, cx] = 0    # 빈 공간
```

공간을 5cm 격자로 나눠 벽과 원통 장애물을 기록합니다.  
파티클은 **빈 공간(0)에만** 뿌려집니다. 벽 속에 로봇이 있을 수는 없으니까요.

---

### Step 2 — LiDAR 시뮬레이션 (Ray Casting)

```
로봇 위치에서 360도로 레이저를 쏜다
          ↓
각 레이저가 벽/장애물에 닿는 거리를 기록
          ↓
[1.2m, 2.3m, 0.8m, ...]  ← 36방향의 거리 배열
```

`ray_cast()` 함수가 핵심입니다. 레이저와 벽 선분의 교점을 수학적으로 계산합니다.

**왜 36방향?**  
`LIDAR_RAYS = 36` → 360도 ÷ 36 = 10도 간격으로 측정

---

### Step 3 — 오도메트리 vs 실제 경로

```python
def noisy_odometry(true_delta, noise=0.25):
    # 실제 이동량에 25% 수준의 노이즈를 추가
    n = np.random.randn(3) * noise * ...
    return true_delta + n
```

**핵심:** 오도메트리는 항상 틀립니다. 노이즈가 누적되어 경로가 점점 벗어납니다.  
MCL은 이 오차를 LiDAR로 보정합니다.

---

### Step 4 — MCL 3단계 함수 상세

#### ① Motion Update (예측 단계)

```python
def motion_update(particles, odom_delta):
    # 모든 파티클을 오도메트리만큼 이동
    # + 작은 노이즈 추가 (불확실성 모델링)
    noise = np.random.randn(3) * ...
    noise[:2] *= 0.15   # x, y 노이즈 15%
    noise[2]  *= 0.10   # 방향 노이즈 10%
```

- 로봇이 앞으로 0.4m 갔다면 → 파티클도 모두 앞으로 0.4m 이동
- 단, 바퀴 미끄러짐을 모방하기 위해 작은 랜덤 노이즈를 추가
- 노이즈가 없으면 파티클들이 한 점으로 뭉쳐 불확실성이 사라짐

#### ② Sensor Update (관측 단계)

```python
def sensor_update(particles, true_scan, true_pose):
    # 각 파티클 위치에서 가상 LiDAR 스캔 생성
    pred_scan = get_scan(p)
    # 실제 스캔과 비교 → 차이가 작을수록 가중치 높음
    diff = true_scan - pred_scan
    weights[i] = exp(-0.5 * sum(diff²) / σ²)
```

**비유:** 당신이 눈을 가리고 서울 지하철에 있다고 상상해보세요.  
눈을 뜨고 "에스컬레이터가 왼쪽, 기둥이 오른쪽"이라는 정보를 얻으면  
지도를 보고 "아, 여기는 강남역 3번 출구 쪽이구나"를 알 수 있습니다.  
→ **센서 데이터와 지도를 매칭해 위치를 좁혀나가는 원리**

### Step 5 — 한 스텝 시각화로 확인하기

4개 그래프가 MCL의 한 사이클을 보여줍니다:

| 그래프 | 파티클 상태 | 의미 |
|--------|------------|------|
| ① Global Localization | 맵 전체에 고르게 분포 | "로봇 위치를 전혀 모른다" |
| ② Motion Update | 약간 이동 + 퍼짐 | "오도메트리로 이동했지만 불확실" |
| ③ Sensor Update | 색깔이 다름 (빨강=높은 가중치) | "LiDAR와 일치하는 파티클이 두드러짐" |
| ④ Resampling | 한 곳에 뭉침 | "높은 가중치 파티클만 살아남음" |

- **Frame 4~9:** 파티클이 특정 영역으로 모이기 시작
- **Frame 19~끝:** 파티클이 실제 위치 근처에 밀집 (위치 추정 성공)

## 5. 자주 하는 실수 & 주의사항

### ❌ "파티클 수가 많을수록 무조건 좋다?"
많을수록 정확하지만 연산량도 비례해 증가합니다.  
실제 ROS2 AMCL에서는 `min_particles ~ max_particles` 범위를 동적으로 조절합니다.

### ❌ "파티클이 한 곳에 뭉쳤으면 완료?"
리샘플링만 계속하면 파티클 다양성이 사라져 **파티클 고갈(Particle Depletion)** 이 발생합니다.  
그래서 리샘플링 시 `+ np.random.randn(...) * [0.02, 0.02, 0.03]` 소량의 노이즈를 다시 추가합니다.

한 곳에 뭉치는 상황은 두 가지로 나뉩니다:

**경우 1 — 틀린 위치에 뭉쳤을 때 (더 심각)**

```
실제 로봇:  ★ (여기 있음)
파티클들:   ●●●●● (저기에 몰려있음)

센서 업데이트 → 저기서 쏜 레이저 vs 실제 레이저 비교
             → 모두 비슷하게 틀림
             → 상대적으로 조금 덜 틀린 것만 복제됨
             → 계속 같은 틀린 위치 근처만 뱅뱅 돔
```

파티클이 다양하게 퍼져있어야 "저기가 더 맞는 것 같다"고 비교할 수 있는데,  
이미 한 곳에 뭉쳐있으면 **탈출구가 없습니다.**

**경우 2 — 맞는 위치에 뭉쳤어도 로봇이 갑자기 이동하면?**

```
파티클들: ●●●●● (이전 정답 위치에 고정)
실제 로봇: ★ (전혀 다른 곳으로 옮겨짐)

→ 모든 파티클이 새 위치 근처에 없음
→ 센서 업데이트해도 가중치가 전부 0에 가까움
→ 회복 불가능
```

이것이 **납치 로봇 문제(Kidnapped Robot Problem)** 입니다. (→ 6절 참고)

**핵심:**
> **다양성(diversity) = 불확실성을 표현하는 능력**  
> 파티클이 한 곳에 뭉친다 = "나는 확실하다"고 선언하는 것  
> → 틀렸을 때 회복할 수단이 사라짐

### ❌ "오도메트리가 없어도 되지 않나?"
LiDAR만으로는 두 시점 사이 이동을 알 수 없습니다.  
오도메트리(Motion Update)가 없으면 파티클이 제자리에 머물러 추적이 불가능합니다.

## 6. MCL vs AMCL 차이

| | MCL | AMCL (Adaptive MCL) |
|--|-----|---------------------|
| 파티클 수 | 고정 | 불확실성에 따라 자동 조절 |
| 납치 로봇 문제 | 대응 불가 | 랜덤 파티클 추가로 대응 |
| ROS2 | 직접 구현 필요 | `nav2_amcl` 패키지로 바로 사용 가능 |

**납치 로봇 문제:** 위치를 잘 알고 있던 로봇을 갑자기 다른 곳으로 옮겨놓으면  
파티클이 이전 위치에 뭉쳐 있어 새 위치를 못 찾는 문제  
→ AMCL은 주기적으로 랜덤 파티클을 추가해 이를 해결

---

## 7. 수식 없이 이해하는 베이즈 필터

MCL은 **베이즈 필터**의 한 구현입니다:

```
믿음(t) = P(위치 | 센서) ∝ P(센서 | 위치) × 예측된 믿음(t-1)
  ↑               ↑                ↑
현재 추정      Sensor Update    Motion Update
```

쉽게 말하면:
> "이전에 알고 있던 것(Motion Update) + 새로운 센서 정보(Sensor Update) = 현재 최선의 추정"

---

## 8. ROS2 AMCL과의 연결

이 실습에서 구현한 것이 실제 ROS2에서는:

| 실습 코드 | ROS2 AMCL |
|----------|-----------|
| `init_particles()` | 초기 포즈 또는 `initialpose` 토픽 |
| `motion_update()` | `/odom` 토픽 구독 |
| `sensor_update()` | `/scan` 토픽 구독 + 지도 매칭 |
| `resample()` | 내부 KLD-샘플링 |
| 추정 위치 출력 | `/amcl_pose` 토픽 발행 |

---

## 핵심 요약

1. **파티클 = 위치 가설들** → 처음엔 맵 전체에 뿌린다
2. **Motion Update** → 오도메트리로 파티클 이동 (+ 노이즈로 불확실성 유지)
3. **Sensor Update** → LiDAR 비교로 가중치 계산 (맞는 파티클 강조)
4. **Resampling** → 가중치 높은 파티클 복제, 낮은 것 제거
5. **반복할수록** 파티클이 실제 위치로 수렴 → 위치 추정 성공
