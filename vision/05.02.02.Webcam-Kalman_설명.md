## 1. 이 프로그램이 하는 일

```
웹캠 영상 → YOLOv8으로 사람 탐지 → 칼만 필터로 위치 안정화 → 화면 출력
```

### 화면에서 볼 수 있는 것

| 색상 | 의미 |
|------|------|
| 🔴 빨간 점 | YOLO가 매 프레임마다 탐지한 원본 중심점 (떨림 있음) |
| 🔵 파란 점 | 칼만 필터가 보정한 중심점 (부드럽게 안정화) |
| 🟡 노란 선 | 두 점의 차이를 시각적으로 연결 |

**핵심 목표**: YOLO만 쓰면 위치가 프레임마다 픽셀 단위로 떨립니다.  
칼만 필터를 통해 이 떨림을 줄이고, 부드럽게 따라가도록 합니다.

---

## 2. 왜 칼만 필터가 필요한가?

### YOLO의 한계

YOLO는 프레임마다 **독립적으로** 바운딩박스를 계산합니다.  
즉, 이전 프레임의 정보를 전혀 사용하지 않습니다.

```
프레임 1: 사람 중심점 (320, 240)
프레임 2: 사람 중심점 (318, 243)  ← 실제로 움직이지 않았는데 값이 튀었다
프레임 3: 사람 중심점 (323, 239)  ← 또 튀었다
```

이런 노이즈(떨림)가 있으면:
- 로봇이 카메라를 향하게 할 때 계속 방향이 흔들립니다
- 속도를 계산하면 엉터리 값이 나옵니다

### 칼만 필터의 아이디어

> "이전까지의 움직임 패턴을 보면, 다음 위치를 **예측**할 수 있다.  
>  YOLO 측정값과 예측값을 **신뢰도에 따라 섞으면** 더 안정적이다."

---

## 3. 칼만 필터의 두 단계

칼만 필터는 매 프레임마다 두 단계를 반복합니다.

```
┌─────────────────────────────────────────────┐
│              매 프레임 반복                   │
│                                              │
│  ① PREDICT  ─────────────────────────────►  │
│    "이전 상태 + 운동 모델로 다음 위치 예측"    │
│                                              │
│  ② UPDATE  ──────────────────────────────►  │
│    "YOLO 측정값과 예측값을 섞어서 보정"        │
└─────────────────────────────────────────────┘
```

### 단계별 비유

| 단계 | 비유 |
|------|------|
| **Predict** | 어제 날씨 + 기상 모델 → 오늘 날씨 예보 |
| **Update** | 예보 + 실제 온도계 측정값 → 최종 판단 |

## 4. 수학식 → 파이썬 코드 번역

### 4-1. 상태 벡터 (State Vector)

칼만 필터는 "현재 상태"를 하나의 벡터로 표현합니다.

**수식**:
$$\mathbf{x} = \begin{bmatrix} c_x \\ v_x \\ c_y \\ v_y \end{bmatrix}$$

| 변수 | 의미 |
|------|------|
| $c_x$ | x 방향 중심 위치 (픽셀) |
| $v_x$ | x 방향 속도 (픽셀/프레임) |
| $c_y$ | y 방향 중심 위치 (픽셀) |
| $v_y$ | y 방향 속도 (픽셀/프레임) |

**파이썬 코드**:
```python
self.x = np.zeros((4, 1))
# → 4행 1열 열벡터: [[cx], [vx], [cy], [vy]]
```

---

### 4-2. 상태 전이 행렬 A (등속 운동 모델)

"지금 상태"에서 "다음 상태"로 어떻게 바뀌는지 정의합니다.

**물리 법칙 (등속 운동)**:
```
다음 위치 = 현재 위치 + 속도 × 시간
다음 속도 = 현재 속도 (등속이므로 변화 없음)
```

**수식으로 표현**:
$$\mathbf{x}_{k+1} = A \cdot \mathbf{x}_k$$

$$A = \begin{bmatrix} 1 & dt & 0 & 0 \\ 0 & 1 & 0 & 0 \\ 0 & 0 & 1 & dt \\ 0 & 0 & 0 & 1 \end{bmatrix}$$

**직접 계산해보면**:
$$\begin{bmatrix} c_x' \\ v_x' \\ c_y' \\ v_y' \end{bmatrix} = \begin{bmatrix} 1 & dt & 0 & 0 \\ 0 & 1 & 0 & 0 \\ 0 & 0 & 1 & dt \\ 0 & 0 & 0 & 1 \end{bmatrix} \begin{bmatrix} c_x \\ v_x \\ c_y \\ v_y \end{bmatrix} = \begin{bmatrix} c_x + v_x \cdot dt \\ v_x \\ c_y + v_y \cdot dt \\ v_y \end{bmatrix}$$

즉:
- `c_x' = c_x + vx * dt` → 위치 = 현재위치 + 속도×시간 ✓
- `v_x' = v_x` → 속도는 그대로 ✓

**파이썬 코드**:
```python
self.A = np.array([
    [1, dt, 0,  0],
    [0,  1, 0,  0],
    [0,  0, 1, dt],
    [0,  0, 0,  1]
], dtype=float)
```

---

### 4-3. 센서 행렬 C (무엇을 측정하는가)

YOLO는 `(cx, cy)` 위치만 알려줍니다. 속도는 측정할 수 없습니다.  
C 행렬은 "상태 벡터 중 어느 부분을 측정하는가"를 정의합니다.

**수식**:
$$\mathbf{z} = C \cdot \mathbf{x}$$

$$C = \begin{bmatrix} 1 & 0 & 0 & 0 \\ 0 & 0 & 1 & 0 \end{bmatrix}$$

**직접 계산해보면**:
$$\begin{bmatrix} c_x \\ c_y \end{bmatrix} = \begin{bmatrix} 1 & 0 & 0 & 0 \\ 0 & 0 & 1 & 0 \end{bmatrix} \begin{bmatrix} c_x \\ v_x \\ c_y \\ v_y \end{bmatrix}$$

즉, 4차원 상태 벡터에서 위치만 꺼냅니다. 속도(2번째, 4번째 요소)는 무시합니다.

**파이썬 코드**:
```python
self.C = np.array([
    [1, 0, 0, 0],
    [0, 0, 1, 0]
], dtype=float)
```

---

### 4-4. PREDICT 단계

**수식**:
$$\hat{\mathbf{x}}_k^- = A \cdot \hat{\mathbf{x}}_{k-1}$$
$$P_k^- = A \cdot P_{k-1} \cdot A^T + Q$$

| 기호 | 의미 |
|------|------|
| $\hat{\mathbf{x}}_k^-$ | k번째 프레임의 예측 상태 |
| $P$ | 공분산 행렬 (상태 추정의 불확실성) |
| $Q$ | 프로세스 노이즈 (모델이 완벽하지 않은 정도) |

**파이썬 코드**:
```python
def predict(self):
    self.x = self.A @ self.x          # x = A * x  (@ 는 행렬곱)
    self.P = self.A @ self.P @ self.A.T + self.Q  # P = A*P*A^T + Q
    return self.x[0, 0], self.x[2, 0]  # cx, cy 반환
```

> `@` 연산자는 파이썬의 **행렬 곱셈** 연산자입니다.  
> `A @ B` 는 수학의 $A \cdot B$ 와 같습니다.  
> `A.T` 는 행렬의 **전치(Transpose)** 입니다 ($A^T$).

---

### 4-5. UPDATE 단계

예측값과 실제 YOLO 측정값을 섞는 단계입니다.

**수식 전체**:

1. **Innovation (측정 잔차)**: 측정값 - 예측값  
$$\tilde{\mathbf{y}} = \mathbf{z} - C \cdot \hat{\mathbf{x}}^-$$

2. **Innovation 공분산**:  
$$S = C \cdot P^- \cdot C^T + R$$

3. **칼만 게인** (예측 vs 측정 신뢰도 비율):  
$$K = P^- \cdot C^T \cdot S^{-1}$$

4. **상태 보정**:  
$$\hat{\mathbf{x}} = \hat{\mathbf{x}}^- + K \cdot \tilde{\mathbf{y}}$$

5. **공분산 보정**:  
$$P = (I - K \cdot C) \cdot P^-$$

**파이썬 코드와 1:1 대응**:
```python
def update(self, cx, cy):
    z = np.array([[cx], [cy]], dtype=float)          # 측정값 벡터 z

    innovation = z - self.C @ self.x                 # ỹ = z - C*x
    S = self.C @ self.P @ self.C.T + self.R          # S = C*P*C^T + R
    K = self.P @ self.C.T @ np.linalg.inv(S)         # K = P*C^T * S^(-1)

    self.x = self.x + K @ innovation                 # x = x + K*ỹ
    self.P = (np.eye(4) - K @ self.C) @ self.P       # P = (I - K*C)*P

    nis = float(innovation.T @ np.linalg.inv(S) @ innovation)  # NIS 계산
    return self.x[0, 0], self.x[2, 0], nis           # cx, cy, NIS 반환
```

> `np.linalg.inv(S)` 는 행렬 $S$의 **역행렬** $S^{-1}$입니다.  
> `np.eye(4)` 는 4×4 **단위행렬** $I$입니다.

---

### 칼만 게인 K의 직관적 의미

$$K = \frac{P^-}{P^- + R}$$  *(단순화된 1차원 표현)*

| 상황 | K 값 | 결과 |
|------|------|------|
| $R$ 크다 (YOLO 신뢰도 낮음) | K → 0 | 예측값 위주로 |
| $P^-$ 크다 (예측 신뢰도 낮음) | K → 1 | 측정값 위주로 |
| 균형 | K → 0.5 | 둘을 반반씩 섞음 |

## 5. 클래스 내부 변수들의 의미

```python
self.Q = np.eye(4) * 0.1    # 프로세스 노이즈
self.R = np.eye(2) * 50.0   # 센서 노이즈
self.P = np.eye(4) * 500    # 초기 공분산
```

| 변수 | 의미 | 값이 크면 |
|------|------|-----------|
| `Q` | 운동 모델을 얼마나 못 믿는가 | 측정값을 더 따라감 |
| `R` | YOLO 탐지값을 얼마나 못 믿는가 | 예측값을 더 따라감 |
| `P` | 현재 상태 추정의 불확실성 | 초기엔 크게, 시간이 지나면 자동으로 줄어듦 |

> **`P = 500`으로 크게 시작하는 이유**:  
> 프로그램 시작 시 사람이 어디 있는지 전혀 모르므로,  
> "나는 지금 위치를 전혀 모른다"는 의미로 불확실성을 크게 설정합니다.  
> 몇 프레임이 지나면 칼만 필터가 자동으로 P를 줄여나갑니다.

## 6. 전체 실행 흐름 (Flow)

```
프로그램 시작
    │
    ├─ YOLOv8 모델 로드 (yolov8n.pt)
    ├─ 웹캠 열기
    ├─ BBoxKalmanTracker 생성
    │
    └─ while True: (매 프레임)
           │
           ├─ 1. 웹캠에서 프레임 읽기
           │
           ├─ 2. YOLO로 사람 탐지
           │       └─ 탐지 없으면 → 그냥 화면 출력 후 다음 프레임
           │
           ├─ 3. 신뢰도 가장 높은 사람 1명 선택
           │       └─ cx, cy 추출
           │
           ├─ 4. 빨간 점 그리기 (YOLO 원본)
           │
           ├─ 5. 칼만 필터 처리
           │       ├─ (최초 1회) init(cx, cy) → 초기화
           │       ├─ predict()  → 이전 상태로 현재 예측
           │       └─ update(cx, cy) → YOLO값으로 보정
           │
           ├─ 6. 파란 점 그리기 (칼만 보정값)
           │
           ├─ 7. NIS 기록
           │
           └─ 8. 'q' 키 눌리면 종료
                   └─ nis_log.csv 저장
```

## 7. 시각화 요소 해설

```python
# 빨간 점: YOLO 원본 중심점
cv2.circle(annotated, (int(cx), int(cy)), 5, (0, 0, 255), -1)
#                                          ↑반지름  ↑색(BGR)  ↑채움

# 파란 점: 칼만 보정 중심점
cv2.circle(annotated, (int(filtered_cx), int(filtered_cy)), 8, (255, 0, 0), -1)

# 두 점을 잇는 선
cv2.line(annotated, (int(cx), int(cy)), (int(filtered_cx), int(filtered_cy)),
         (0, 255, 255), 1)
#          ↑시작점              ↑끝점                                ↑색(노란)  ↑두께
```

> OpenCV의 색상 순서는 **BGR** (Blue, Green, Red)입니다. RGB가 아닙니다!  
> `(255, 0, 0)` = 파란색, `(0, 0, 255)` = 빨간색

## 8. NIS란 무엇인가?

**NIS (Normalized Innovation Squared)**: 칼만 필터가 얼마나 잘 동작하는지 평가하는 지표

**수식**:
$$\text{NIS} = \tilde{\mathbf{y}}^T \cdot S^{-1} \cdot \tilde{\mathbf{y}}$$

**파이썬**:
```python
nis = float(innovation.T @ np.linalg.inv(S) @ innovation)
```

### NIS 해석

| NIS 값 | 의미 |
|--------|------|
| 너무 큼 (>> 측정 차원수) | R이 너무 작다 → YOLO를 너무 믿는다 |
| 적당 (측정 차원수 ≈ 2) | 필터가 잘 동작 중 |
| 너무 작음 (<< 측정 차원수) | R이 너무 크다 → YOLO를 너무 안 믿는다 |

> 이 코드에서 측정 차원수 = 2 (cx, cy)  
> 평균 NIS ≈ 2 근방이면 필터가 잘 설계된 것입니다.  
> 종료 후 `05.02.03.Kalman-NIS-Eval.py`로 이 값을 분석할 수 있습니다.

## 9. 파라미터 튜닝 가이드

### Q (프로세스 노이즈)를 바꾸면?

```python
self.Q = np.eye(4) * 0.1   # 기본값
```

| Q 값 | 효과 |
|------|------|
| 크게 (예: 10.0) | 모델을 못 믿음 → 측정값을 빠르게 따라감 → 반응 빠르지만 떨림 있음 |
| 작게 (예: 0.001) | 모델을 믿음 → 예측값 위주 → 부드럽지만 느리게 반응 |

### R (센서 노이즈)를 바꾸면?

```python
self.R = np.eye(2) * 50.0  # 기본값
```

| R 값 | 효과 |
|------|------|
| 크게 (예: 500.0) | YOLO를 못 믿음 → 칼만이 독자적으로 움직임 → 과도하게 부드러움 |
| 작게 (예: 1.0) | YOLO를 믿음 → YOLO값에 바짝 따라감 → 떨림 증가 |

### USE_KALMAN을 끄면?

```python
USE_KALMAN = False
```

칼만 필터 없이 YOLO 원본만 표시합니다.  
두 모드를 비교하면 칼만 필터의 효과를 직접 눈으로 확인할 수 있습니다.
